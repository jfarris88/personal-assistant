## Tools & Systems

- **Cortex (getcortexapp.com)** — O'Reilly's software/service catalog & engineering intelligence platform (replacing Surveyor/Metabase). Tracks service/repo ownership via `cortex.yaml`, integrates GitHub/Datadog/Slack, and has "scorecards" for standards compliance. **API key: "Cortex API (read)"** in 1Password Employee vault (username `jfarris-cli`, created 2026-07-02) — Jay's personal read-only key. **Use for:** looking up service/repo ownership or team context during helpdesk/IT triage and research requests. Distinct from the separate Cortex service-account key requested under [AM-2301](https://intranet.oreilly.com/jira/browse/AM-2301) (Theo Moser's `signal-iq` leadership dashboard, still Pending Approval, meant for GCP Secret Manager — not this key). Extent of intended use still TBD per Jay (2026-07-02).

**Verified working 2026-07-02** — API base `https://api.getcortexapp.com`, auth via `Authorization: Bearer <key>`. Confirmed use case: the **SOC2 Compliance scorecard** (`GET /api/v1/scorecards/soc2-compliance`, scores at `.../soc2-compliance/scores`) is the live "report" of repos subject to SOC2 — scope = all `service`-type catalog entities *except* those tagged with the `exclude-from-soc2` group (336 in scope / 52 excluded as of 2026-07-02). Checks vuln thresholds + branch protection/required approvals. Runbook: `devdocs.common-build.gcp.oreilly.com/operations/security/soc.html#provide-a-list-of-projects-that-are-included-in-the-platform`.

**Known API limitation — "what does team X own?" queries (found 2026-07-02):** There's no working server-side filter for this with the read key. `GET /api/v1/catalog` never returns per-entity `ownersV2`/`owners` data (always `null`) regardless of query params tried (`ownerTeamTag`, `owningTeamTags`, `teamTag`, `team`, `includes=owners` — all silently ignored, still return the full 421-entity catalog). The real CQL endpoint (`POST /api/v1/queries`) returns **403 Forbidden** with this key — no query-builder access, catalog/scorecard reads only. **Working approach:** individual entity detail (`GET /api/v1/catalog/{tag}`) *does* include full `ownersV2.teams`, so the only way found so far is: page through `/api/v1/catalog` for all entity tags, then hit `/api/v1/catalog/{tag}` per entity (N+1, ~421 calls as of 2026-07-02) and filter client-side for the team tag (e.g. `oreillymedia-metacon`). Works but slow — fine for a one-off, not for frequent/repeated use. Team tag format is the Cortex `teamTag` (e.g. `oreillymedia-metacon`), **not** the git/idpGroup slug (e.g. `oreillymedia/metacon`) — those differ and only the former matches `ownersV2.teams[].tag`. If asked again, re-check whether Cortex has since added a working filter/bulk-by-team endpoint before repeating the N+1 workaround.

- **Chassis service admin access (Groot/Django groups)** — Chassis-based GCP services (e.g. `<service>.platform.gcp.oreilly.com/admin`) control admin access via Groot-synced Django Groups, not self-service. Granting access requires the service's owning team (find via Cortex) to create/confirm a permissions Group, then `@guardian-devs` in Slack to add users to it. Full process + example (SOL-106969 / feedback-service): [chassis-service-admin-access-process.md](../notes/chassis-service-admin-access-process.md).

- **Claude billing/analytics visibility — Team vs. Enterprise plan** (confirmed 2026-07-10, re: AM-2431) — O'Reilly is currently on Claude's **Team** plan (144 seats, per Org settings > Billing screenshot 2026-07-10), with an Enterprise upgrade being considered but not yet done.
  - **On Team plan (current state):** No custom roles. Only **Owner/Primary Owner** can see Org settings > Billing (spend). **Admin** can manage members but cannot see Billing. There is no way to grant someone view-only spend/billing access without making them a full Owner.
  - **On Enterprise plan (after upgrade):** Custom roles become available — you can create a role with Billing → "Can view" and Analytics → "Can view" while leaving Identity & Access / User Management / Privacy / Libraries at "No access", then assign it via a Group (Org settings > Roles, Org settings > Groups). This is the path to give an exec view-only reporting access without full admin. Enterprise also exposes a read-only **Analytics API** for pulling usage data into external dashboards. No API exists to *provision* roles/permissions themselves on either plan — role setup is UI-only via Org settings.
  - **Implication for AM-2431 (Julie Baron):** on the current Team plan, the only way to give her billing/reporting visibility is to make her Owner or Primary Owner (full access, not scoped) — there's no view-only middle ground until the Enterprise migration happens.
